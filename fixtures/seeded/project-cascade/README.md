# project-cascade

`core` U-001 ships `core/data.txt` (C-001, pinned by `api`); core U-002 ships
a note. `api` U-001 depends on the pin and its Verification row checks that
`core/data.txt` is exactly `v1`; api U-002 follows U-001.

Three canned trees: `solution/` (data is `v1`), `solution-v2/` (core U-001
regenerates with `v2`: the api U-001 row now fails) and `solution-regen/`
(core U-001 regenerated byte-identically to `solution/`). Point `STUB_REF` at
one of them when core U-001 is rebuilt: from `solution-v2` the downstream
re-check fails (the culprit scenario), from `solution-regen` it passes
unchanged.
